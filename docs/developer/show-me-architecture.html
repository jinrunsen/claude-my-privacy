04 / VERIFICATION
不同检查，回答不同问题。
这里介绍验证分层，不代表刚刚完成了一次测试。前置条件与覆盖范围见验证说明。

      
A
模块逻辑是否符合约定？
Node 测试覆盖替换、配置、工具策略、内容处理、审计和命令名称。
plugins/my-privacy/tests/*.test.mjs
B
插件是否正确接入宿主？
清单验证与 Mod 测试检查事件接入、仅显示恢复、元数据、失败回退，以及源消息保持不变。
tests/hooks.test.ts · tests/display.test.ts
C
原生工具是否拿到正确参数？
隔离 CLI 环境使用虚构词表和可控模型响应，验证真实工具调用。
verification/run.sh → run-targeted.py
D
回复恢复后，历史是否保持化名？
可选的离线终端检查验证回复恢复、存储文本与下一轮模型历史保留化名，以及 --print 输出保留化名。
python3 verification/run-display.py
E
中英文文档是否保持同步？
检查器比对结构、代码、本地链接与文件指纹；语义仍需要复核。
scripts/check-translations.py

05 / BOUNDARIES
流程之外，仍有边界。
MyPrivacy 减少指定词在支持文本中的暴露，不能保证每个请求或记录都已脱敏。
  • 只处理指定词。没有通用邮箱、手机号或证件号识别；匹配为不区分大小写的子串替换。
  • 尽力替换。替换失败可能放行原文；结果处理失败不会重放工具。
  • 覆盖有限。不支持的媒体和部分固定历史、快照可能保持原样。session.send 处理 text 字段，不是最终请求的总过滤器。
  • 显示恢复有明确范围。仅恢复 AssistantMessage 文本，不恢复用户消息和工具显示。跨块拆分的化名可能保留；真实流式输出、复制或导出及其他客户端尚未验证；普通 --print 保留化名。
  • 执行仍会使用原文。原生权限继续生效。Bash 按字面恢复且不自动转义；目标工具或服务可能收到真实名称或账号。
